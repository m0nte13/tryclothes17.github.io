# Безопасность сайта MONTE

Сайт состоит из статических страниц:

- `index.html` — магазин;
- `checkout.html` — оформление и оплата;
- `tryon.html` — примерка через камеру.

Сервера нет: корзина и заказ живут в браузере, оплата работает в демо-режиме.
Ниже описано, что защищено сейчас и что нужно сделать перед запуском настоящего магазина.

---

## 2. Content-Security-Policy

Политика задана тегом `<meta http-equiv="Content-Security-Policy">` в начале каждой страницы.

| Директива | `index.html` | `checkout.html` | `tryon.html` |
|---|---|---|---|
| `default-src` | `'none'` — всё, что не разрешено явно, запрещено | так же | так же |
| `script-src` | только свои файлы и встроенные скрипты | так же | плюс `cdn.jsdelivr.net` и `'wasm-unsafe-eval'` для MediaPipe |
| `img-src` | свои, `images.unsplash.com`, `data:`/`blob:` | свои, `images.unsplash.com` | свои, `data:`, `blob:` (камера, загруженные фото) |
| `connect-src` | только свой домен | `'none'` — странице оплаты запрещены любые сетевые запросы | свой домен + jsDelivr и Google Storage (модели MediaPipe) |
| `form-action` | `'self'` | `'none'` — форма оплаты физически не может никуда отправиться | `'none'` |
| `object-src`, `base-uri` | `'none'` | `'none'` | `'none'` |

**Почему разрешён `'unsafe-inline'` для скриптов.** Код страниц написан прямо внутри HTML. Без этого сайт не открывался бы двойным кликом по файлу.
Главная защита от XSS — экранирование при выводе (`escapeHtml` / `esc`) и проверка входных данных. CSP — второй рубеж: даже при ошибке чужой скрипт не загрузится с постороннего сервера, а на странице оплаты не сможет ничего отправить.

**Как ужесточить для продакшена.** Вынести скрипты в отдельные файлы (`app.js`, `checkout.js`), убрать атрибуты `onerror` у картинок и удалить `'unsafe-inline'` из `script-src`.

Источник `file:` в `script-src` нужен только для открытия страниц с диска. На хостинге он ни на что не влияет.

## 3. Данные покупателя

- **Сеть.** Сайт ничего не отправляет: ни контакты, ни адрес, ни данные карты. Это закреплено CSP на `checkout.html` (`connect-src 'none'`, `form-action 'none'`).
- **Данные карты.** Проверяются только в браузере (алгоритм Луна, срок, CVC), нигде не сохраняются и стираются после «оплаты» или ухода со страницы. На экране успеха видны только последние 4 цифры.
- **Хранилище браузера.** В `localStorage` лежит только корзина (id товара, размер, количество). При переходе к оплате в `sessionStorage` кладётся состав заказа. После оплаты оба значения удаляются.
- **Камера** в примерке работает только локально: кадры никуда не уходят, поток выключается при уходе со страницы.

## 4. Хостинг: заголовки сервера

Часть защиты задаётся только HTTP-заголовками — тег `<meta>` для неё не работает. Готовый файл `_headers` лежит в проекте; его понимают Netlify и Cloudflare Pages.

| Заголовок | Зачем |
|---|---|
| `X-Frame-Options: DENY` и `frame-ancestors 'none'` | Сайт нельзя встроить в чужую страницу (кликджекинг) |
| `Strict-Transport-Security` | Браузер открывает сайт только по HTTPS |
| `X-Content-Type-Options: nosniff` | Браузер не выполняет файлы с неверным типом |
| `Permissions-Policy` | Камера разрешена только своим страницам; микрофон и геолокация запрещены |
| `Cache-Control: no-store` на `checkout.html` | Страница оплаты не сохраняется в кеше |

**nginx** — те же заголовки:

```nginx
add_header X-Frame-Options "DENY" always;
add_header Content-Security-Policy "frame-ancestors 'none'" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header Permissions-Policy "camera=(self), microphone=(), geolocation=(), payment=(self)" always;
location = /checkout.html { add_header Cache-Control "no-store" always; }
```

**Важно:** камера в браузере работает только по **HTTPS**. Без сертификата примерка на телефоне не включится.

## 5. Перед запуском настоящего магазина

Эти пункты нельзя закрыть статическими HTML-файлами — нужен сервер или сторонние сервисы.

1. **Оплата только через платёжного провайдера** (ЮKassa, CloudPayments, Т-Касса и т. п.) с их защищённой формой или виджетом. Данные карты не должны проходить через ваш сайт и сервер — иначе магазин обязан соответствовать стандарту PCI DSS. Текущую демо-форму карты при подключении провайдера нужно **удалить**.
2. **Цены считает сервер.** Сейчас сумма заказа считается в браузере, и её можно подменить. Сервер должен брать цены, скидки и промокоды из своей базы, а не из запроса.
3. **Промокоды — только на сервере.** Сейчас код `MONTE10` виден в исходнике страницы.
4. **Персональные данные по 152-ФЗ.** Имя, телефон, e-mail и адрес — персональные данные. Нужны настоящая политика конфиденциальности, согласие на обработку и хранение данных на серверах в РФ.
5. **Защита формы заказа на сервере:** CSRF-токен, ограничение частоты запросов (rate limit), капча от ботов.
6. **Обновление зависимостей.** Раз в несколько месяцев проверяйте новые версии Tailwind и MediaPipe. Для продакшена Tailwind лучше собирать через CLI в обычный CSS-файл: так не нужен JavaScript для стилей и проще убрать `'unsafe-inline'`.

## 6. Как проверить

- Откройте инструменты разработчика (F12) → вкладка Console. Нарушения CSP видны там как `Refused to load…`. Если сообщений нет, политика не мешает работе сайта.
- [securityheaders.com](https://securityheaders.com) и [observatory.mozilla.org](https://developer.mozilla.org/en-US/observatory) проверят заголовки после публикации сайта.
